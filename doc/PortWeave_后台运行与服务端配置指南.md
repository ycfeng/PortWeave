# PortWeave 后台运行与服务端配置指南

本指南面向 PortWeave 用户，说明如何让端口映射在后台稳定运行，同时尽量少触发系统的“后台耗电过快”提示。

---

## 1. 选择省电档位

位置：设置 → 后台运行 → 省电档位。

| 档位 | 后台保活 | 后台连不上时 | 空闲时 | 适用场景 |
|---|---|---|---|---|
| 实时 | 始终使用映射里配置的保活间隔 | 熄屏后也按后台节奏继续重试 | 保持连接 | 需要随时秒连，并且接受更高的耗电 |
| **均衡**（默认） | 自动拉长到 60s–4min，按网络分别学习安全值 | 连续失败后暂停重试，等网络变化或打开应用再试 | 保持连接 | 大多数人 |
| 省电 | 起点更高，拉长得更快 | 更早暂停重试 | SSH 映射空闲 5 分钟后断开远端会话，本地端口继续监听；有新连接时自动重连，首个连接会慢 1–3 秒 | 偶尔才用的映射 |

说明：

- 无论选哪个档位，应用在前台时都按配置的间隔保活。打开应用时会立即检查一次连接是否还活着。
- “暂停重试”期间，首页显示“暂停重连 · 网络变化或打开应用后继续”，通知栏仍可点“立即重试”。
- 省电档的空闲断开目前只对 SSH 映射生效，STCP 映射不受影响。

---

## 2. 服务端配置建议

服务端主动发出的心跳同样会唤醒手机。如果服务端每 30 秒发一次心跳，手机侧把保活拉得再长也没有用。按下面的建议调整服务端，可以和 PortWeave 的自适应保活配合。

### 2.1 OpenSSH（`/etc/ssh/sshd_config`）

```text
# 推荐：关闭服务端主动探测，由客户端负责保活
ClientAliveInterval 0

# 或者：保留服务端探测，但放宽间隔，并允许连续 3 次没有响应
# ClientAliveInterval 120
# ClientAliveCountMax 3
```

修改后重新加载配置：`sudo systemctl reload sshd`（服务名以发行版为准，有的叫 `ssh`）。

### 2.2 frps（`frps.toml`）

```toml
# yamux 层心跳，默认 30s。可调到 60–120s，前提是中间的 NAT 不会更早回收空闲连接
transport.tcpMuxKeepaliveInterval = 90
```

- 配置项名称以所用 frp 版本的文档为准。旧版 ini 配置写作 `tcp_mux_keepalive_interval`。
- PortWeave 不启用 frp 层的 Ping 心跳，只依靠 yamux 保活。如果 frps 显式设置了 `transport.heartbeatTimeout`，请确认它不会因为收不到客户端 Ping 而断开连接：可以设为 `-1` 关闭这项检查，或者先实际测试一段时间。

### 2.3 中间网络

- 家用路由器和运营商 NAT 回收空闲 TCP 连接的时间从 1 分钟到 1 小时不等。PortWeave 的均衡和省电档会自动试探：保活在某个间隔下失败后，就在这个网络上退回到更短的间隔。
- 如果服务器在公司防火墙后面，空闲超时可能很短。这时可以改用“实时”档，或在映射里把保活间隔调小。

## 3. 手机系统设置

PortWeave 不会默认申请“忽略电池优化”，也不使用常驻唤醒锁、无声音频、双进程互拉等手段。如果映射在后台经常中断，可以手动放宽系统对 PortWeave 的限制。

PortWeave 检测到上次是被系统结束的（Android 11 及以上），会在下次打开时提示一次。设置页的“厂商后台设置”里也提供同样的说明和“打开应用设置”按钮。

常见设置位置如下，具体名称和路径以实际系统版本为准：

| 系统 | 常见设置项 |
|---|---|
| ColorOS / realme UI / OxygenOS | 电池 → 应用耗电管理 → 允许后台行为、允许自启动 |
| OriginOS / Funtouch OS | 电池 → 后台耗电管理 → 允许后台高耗电 |
| HyperOS / MIUI | 应用设置 → 省电策略 → 无限制，并开启自启动 |
| MagicOS / HarmonyOS / EMUI | 应用启动管理 → 关闭自动管理 → 允许后台活动 |
| 通用 | 在多任务界面锁定 PortWeave 的应用卡片 |

## 4. 排查

设置 → 导出脱敏诊断包，其中的计数器可以帮助判断后台在做什么：

| 计数器 | 含义 | 偏高时说明 |
|---|---|---|
| `sshKeepAlivesSent`、`stcpKeepAlivesAnswered` | 后台保活次数 | 保活间隔没有拉长：可能处于“实时”档，或服务端心跳很频繁 |
| `heartbeatDemotions` | 保活间隔被迫缩短的次数 | 中间 NAT 回收空闲连接很快 |
| `sshKeepAliveTimeouts`、`stcpKeepAliveTimeouts` | 保活没有收到响应的次数 | 网络不稳定，或 NAT 回收空闲连接 |
| `dormantRetryWaits` | 进入暂停重试的次数 | 服务端长时间不可达 |
| `sshStandbyEntries`、`sshStandbyResumes` | 省电档下进入待机、按需重连的次数 | — |
| `suppressedEvents` | 后台被合并、没有写入的日志条数 | 连接在后台频繁抖动 |
